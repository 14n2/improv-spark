# Improv Spark — 产品需求文档（PRD）

> 版本：1.0（开发基线）  
> 日期：2026-10-17  
> 状态：九阶段产品决策已确认；尚未开始实现或验收  
> 目标仓库：`improv-spark`（GitHub Public）

## 1. 产品概述

### 1.1 产品定位
Improv Spark 是一个为即兴戏剧演员提供随机灵感提示的轻量 Web 工具。用户打开网页，点击按钮，即从内置的中文地点词库抽取一个地点，用作 Workshop、排练或个人即兴创作的起点。

### 1.2 目标用户与使用场景
- **主要用户**：業餘製造内部成员。
- **使用场景**：Workshop、集体排练、个人创作与练习。
- **访问方式**：公开网址，无需注册和登录；支持微信群分享链接并在微信内置浏览器打开。
- **产品原则**：快速上手、移动端优先、内容清晰、低维护成本。

### 1.3 版本策略
- **V1（Web MVP）**：优先快速开发、部署、内部测试与迭代。
- **V1.x**：根据团员反馈修复问题、调整词库及体验。
- **后续版本**：评估利用 Taro 将 React 业务逻辑迁移/适配至微信小程序；**不承诺零改造复用**。

### 1.4 V1 成功标准
1. 通过第 8 节全部 Definition of Done 验收项。
2. 首批 3 位团员可从网页或微信中的链接完成实际抽取和反馈。
3. 修复全部阻断性 Bug 后发布 V1.0，并向全团分享。

## 3. V1 范围

### 3.1 包含（In Scope）
- 加载内置 JSON 中 40 个互不重复的中文地点。
- 首屏展示产品名、类别“地点”、单张大卡片与抽取按钮。
- 点击后抽取一个地点；单轮不重复，完成 40 个后自动生成新一轮。
- 相邻轮次边界不重复，即新轮第一个地点不得等于上一轮最后一个地点。
- 抽取触发 1–2 秒文字快速切换效果；动画期间防重复点击。
- 动画结束后显示真实结果，并保持到下一次抽取。
- 刷新页面或重新打开页面时开始全新一轮；不保存抽取进度和历史。
- 适配移动浏览器、微信内置浏览器和桌面浏览器。
- 静态构建与 GitHub Pages 部署。

### 3.2 不包含（Out of Scope）
- 地点以外的其他提示类别，如关系、台词、人物。
- 用户编辑/上传/分享词库；管理员界面。
- 登录、账户、数据库、后端 API、云同步。
- 历史记录展示及持久化。
- 单次抽多个地点、音效、自动定时抽取、离线 PWA。
- 多语言版本和微信小程序正式发布。
- 業餘製造品牌署名。

## 4. 功能需求（Functional Requirements）

| ID | 优先级 | 要求 | 可观察结果 |
|---|---|---|---|
| FR-01 | P0 | 加载 40 个中文地点 | 页面加载后可抽取；词库合法且无重复 |
| FR-02 | P0 | 按钮单次抽一个地点 | 每次完成一个最终结果 |
| FR-03 | P0 | 一轮内不重复 | 连续 40 次得到全部 40 个不同地点 |
| FR-04 | P0 | 抽完自动洗牌 | 第 41 次无需额外操作 |
| FR-05 | P0 | 跨轮边界不重复 | 第 41 次不同于第 40 次 |
| FR-06 | P0 | 文字快速切换动画 | 单次总时长 1–2 秒，结束时显示真实结果 |
| FR-07 | P0 | 动画期间防重入 | 快速多次点击不会消耗额外抽取结果 |
| FR-08 | P0 | 结果保持 | 本次结果直到下次抽取前不变 |
| FR-09 | P0 | 刷新/重开重置 | 没有跨刷新持久化状态 |
| FR-10 | P0 | 响应式交互 | 适用于手机和电脑，无横向滚动 |
| FR-11 | P0 | 无音效、无登录、无历史 UI | 页面仅提供必要交互 |
| FR-12 | P0 | 词库由 GitHub 文件维护 | 更改 JSON、合并部署后使用新词库 |

### 4.1 核心用户流程
1. 用户通过浏览器或微信群链接打开页面。
2. 看见标题 “Improv Spark”、地点类别、初始卡片与“抽取地点”按钮。
3. 点击按钮；逻辑层立即锁定本次真实结果，并禁用按钮。
4. 视图层在 1–2 秒内快速显示其他地点文字作为动画效果（不消耗额外实际抽取）。
5. 动画结束后卡片显示真实结果；按钮可再次点击。
6. 完成一轮后，下次点击自动进入洗牌后的新一轮。

### 4.2 状态机
- `idle`：未抽取，显示引导文案。
- `animating`：结果已确定，动画进行中，按钮不可操作。
- `revealed`：结果显示，按钮可操作。
- 页面刷新导致所有状态重新初始化。

### 4.3 随机算法与边界
- 使用 Fisher–Yates 洗牌处理整轮词库；按队列依次取出。
- 每轮 40 个项目恰好出现一次；不要用“随机抽一个并重试到不重复”代替洗牌队列。
- 新轮洗牌时若首项等于上轮末项，调换首项与其他不同的项目。40 项词库保证可调换。
- 在播放动画**前**提交一次真实抽取，动画中的临时文字仅是视觉反馈。
- 若项目在未来变为 0 或 1 个地点，展示配置错误/禁用抽取或调整规则，不能陷入无限循环；V1 数据验证直接要求恰好 40 个合法地点。
- 默认不使用 localStorage/sessionStorage/IndexedDB 保存进度。
- 使用 `Math.random()` 足以满足娱乐性抽取，**不宣称加密安全或公平竞赛级随机性**。

## 5. 数据规范

### 5.1 数据文件
路径：`src/data/locations.json`

```json
{
  "locations": [
    "深夜便利店",
    "机场安检口",
    "医院候诊室"
  ]
}
```

以上只是**格式样例**，不是最终 40 个地点名单。正式内容需在开发时编制与审校。

### 5.2 内容规则
- 恰好 40 条非空中文文本，去除首尾空格；不允许完全重复。
- 简洁、容易理解、适合即兴演出；避免过长导致移动端难以显示。
- 兼顾日常与意外、有开放的戏剧可能性；不预设具体角色或结局。
- 提交前人工审核近义重复和内容适宜性。
- 通过修改 GitHub JSON 并重新构建/发布更新词库。

## 6. UI / UX 设计规范

### 6.1 已确认方向
- **整体**：Playful 趣味创意，但不过度游戏化。
- **配色**：柔和低饱和。
- **字体**：现代无衬线，中英文清晰。
- **卡片**：居中单张大卡片（不叠卡）。
- **动画**：地点文字快速切换，1–2 秒。
- **品牌**：不显示“by 業餘製造”或其他剧团署名。
- **平台**：Mobile First；在桌面居中展示适当宽度。

### 6.2 实施建议（具体数值待视觉验收）
| Token | 值 | 用途 |
|---|---|---|
| `spark-bg` | `#F8F7FC` | 页面背景 |
| `spark-primary` | `#B7BEF5` | 主色、按钮 |
| `spark-pink` | `#F6C9D5` | 少量辅助色 |
| `spark-mint` | `#C7E6D6` | 少量点缀色 |
| `spark-text` | `#303246` | 主要文字 |
| 卡片背景 | `#FFFFFF` | 突出抽取结果 |
| 内容最大宽 | `28rem`～`30rem` | 桌面保持聚焦 |
| 卡片圆角 | `1.5rem` | 柔和、轻松 |
| 卡片关键词 | 约 `2rem`～`2.5rem` | 大字易读，可根据屏宽缩放 |
| 按钮触控高度 | 最低 `48px`，目标约 `52px` | 移动端舒适点击 |

> 配色与尺寸是设计建议，不是产品方逐项明确确认的固定值。发布前需实机查看并校对对比度。

### 6.3 Tailwind CSS v4 样式入口建议

```css
@import "tailwindcss";

@theme {
  --color-spark-bg: #F8F7FC;
  --color-spark-primary: #B7BEF5;
  --color-spark-pink: #F6C9D5;
  --color-spark-mint: #C7E6D6;
  --color-spark-text: #303246;
  --font-sans: "Inter", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
}
```

- 不要求下载自定义字体；系统字体 fallback 必须可用。
- 注意按钮与卡片的文字对比度，不应在浅色按钮上使用纯白小字。
- 保留可见 focus 状态及语义化 `<button>`；视觉动画遵守 `prefers-reduced-motion`，减弱或省略动画但不改变抽取结果。
- 初始文案、抽取中状态和最终结果都需要清晰可辨。

## 9. 测试方案

### 9.1 自动化：随机逻辑
建议使用 Vitest，对以下情况分别建立测试：
1. 40 项地点全部包含且没有重复。
2. 抽取 40 次每个地点恰好出现一次。
3. 第 41 次自动重新洗牌。
4. 第 41 次不等于第 40 次。
5. 抽取结果总在有效词库内。
6. 动画多次触发保护可通过逻辑测试或交互测试确认。
7. 词库为空、只有一项、重复或无效数据时，处理可预测且不会死循环。

### 9.2 手动：页面兼容与可用性
- iPhone Safari：布局、交互、按钮状态、动画。
- iPhone 微信内置浏览器：通过微信群链接打开并完成多次抽取。
- Android 微信内置浏览器：显示、字体、操作与动画。
- 电脑 Chrome / Safari：布局、点击、刷新、构建产物。
- 用长地点名称检验换行和卡片高度。
- 核实键盘焦点、减少动画偏好和小屏适配。
- 对每项问题记录“环境 / 复现步骤 / 预期 / 实际 / 严重度”。

### 10.2 Bug 分级
- **阻断性（Blocker）**：页面打不开、按钮无法抽取、随机规则错误、严重显示故障等；必须先修复。
- **一般问题**：不影响主要流程的视觉细节、轻微动效问题等；记录并按优先级处理，但 V1 仍需满足全部 DoD。
